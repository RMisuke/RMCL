### 1.2 五条判断

1. **引擎与插件平台质量高于"门禁全绿"的一般水准，但门禁存在系统性盲区**。
   617 项测试 + 双 clippy 硬门禁挡住了大部分低级错误，可本次审计仍在**完全没被测试覆盖的路径上**
   找到两个正常使用即触发的 P1（启动优先级/wrapper 必挂、下载校验失败后永久投毒）——
   盲区规律：`launch()` 端到端集成、`rmccc-download` 的网络交互路径、前端组件，恰好都是三方 mock 缺失的地方。
2. **Phase 6（Agent）"文档先行"程度过高，且全部工作未提交**。
   `rmccc-agent` 4,355 行 + ADR-009/010 + 9 份文档更新全部停留在工作树；ADR-010 的隐私承诺约 80% 兑现，
   home 路径脱敏在生产路径是**死代码**（P2-17）。若现在丢失工作树，文档将与现实严重脱节。
3. **插件平台仍是全仓质量标杆，但有三个安全纵深缺口**：dashboard `layout_id` 路径注入（P2-14）、
   UI 桥 HTTP 客户端 fail-open 回退（P2-16）、`network.request` DNS rebinding 残面（P2-19）。
   在"前端/插件不可完全信任"的威胁模型下，这三条与既有权限模型的高标准不匹配。
4. **发布工程是"写了但从未跑通"的占位资产**：e2e job 配置上不可能通过（无 dev server + chrome
   capabilities 对 WebKit 后端，P2-30）；release 签名/公证 Secret 占位（已知）；updater 三处断线
   （配置/权限/偏好齐备但前端零调用）。这与 roadmap Phase 7 的自认一致，但 e2e 的具体断点比文档说的更糟。
5. **体积红线（ADR-011）全面达成且余量扩大**：随工具链更新（rustc 1.99.1, 2026-10-13 构建），
   `strip = true` 恢复生效——GUI 7.91 MiB / CLI 4.84 MiB / helper 1.06 MiB，无需任何手动后处理。

## 3. 架构总结（as-built 摘要）

> 详细分层、DAG、数据布局、设置模型见 [`AUDIT_2026-10-20.md`](AUDIT_2026-10-20.md) §4–§8
> 与 [`ARCHITECTURE.md`](../ARCHITECTURE.md)；此处只更新增量。

### 3.1 四层结构（18 成员）

```
L1 基础    rmccc-error / rmccc-config / rmccc-platform（平台适配层，唯一合法 #[cfg] 所在地）
L2 领域    auth / download / version / launch / modloader / mods / profile
             + plugin（声明式插件）/ dashboard（布局主题）/ logic（WASM 监管）
             + agent（Phase 6：LLM adapter / 凭据 / 会话 / 只读工具）
L3 编排    rmccc-core（CoreContext DI + pipeline 唯一编排入口）
L4 适配    src-tauri（77 IPC）/ src-cli（rmcli）/ src-logic-host（唯一链接 wasmi 的 helper）
```

本轮复核确认的架构健康项：

1. **pipeline 唯一编排**：Tauri（`version.rs:145/171`、`instance.rs:269`、`launch.rs:103/112`）与
   CLI（`context/{version,resource,launch,mod}.rs`）全部经 `pipeline::install_game / commit_install /
   repair_instance / ensure_launch_ready / launch_game`；modloader 安装收敛于
   `core::modloader::install_loader`。未发现新增绕过（唯一例外：CLI `download_status` 只读绕过，P3-29）。
2. **平台 cfg 红线**：10 个核心引擎 crate 生产代码零平台 `#[cfg]`；`rmccc-platform::current()`
   是唯一选择器；Unsupported 后端一律 fail-closed 返回 `UnsupportedPlatform`。
3. **安全设计主线**（复核属实）：AES-256-GCM（随机 12B nonce/信封版本化）、argfile 延迟删除 +
   陈旧文件清扫、`.abnormal` 崩溃标记、`terminate_tree` 进程组（真机烟测）、pre/wrapper 命令不走
   shell（无注入面）、`open_url` scheme 白名单（含 `-a Calculator` 注入测试）。
4. **插件平台**：`.rmcpkg` 双重独立校验（inspect + extract 都做 zip-slip/压缩比/symlink/类型白名单，
   extract 用 `take()` 硬限实际写入量）、安装事务快照回滚、升级只收缩不扩权（pending 语义）、
   18 项能力分级 + 每调用复核 + denied 审计、WASM 沙箱四层限制——与 ADR-003~007 逐条对上。

### 3.2 Agent 平台（Phase 6 新增，未提交）

- `credentials`：`FileCredentialStore`（AES-256-GCM，`private/agent.key` 0600，与账号 vault key 隔离）；
  端点策略远程仅 HTTPS / 本地仅 loopback HTTP（拒绝 `192.168.x.x`、`localhost.evil.com`、`file://`）。
- `llm`：`OpenAiCompatibleProvider`——SSE 增量解析、指数退避（仅 429/5xx/网络）、最小间隔限流、
  `CancelToken` 逐 chunk 检查；重试只发生在响应头之前（不会重复发送 Delta）。
- `session`：`agent/sessions/<id>.jsonl` 9 种白名单事件（提示词/输出只存 sha256+长度）、
  `agent/tasks/<id>.json` 原子写快照、id 校验 `[A-Za-z0-9_-]{1,64}`（路径穿越唯一拦截点）、
  30 天 mtime 裁剪。
- `tools`：`ToolRegistry`（JSON Schema 校验 + 四级风险门禁：Phase 6 只放行 `read_only`）；
  内置 `versions.installed` / `mods.installed` / `mods.dependency_scan`（fabric.mod.json 依赖解析 →
  dry-run `ModInstallPlan`，审计 P3-2 由此销账）。
- **未被 `src-tauri`/`src-cli` 依赖**：`cargo tree -p rmccc` 中 0 处 `rmccc-agent`，主可执行体积
  不受影响（本轮体积实测间接证实）。IPC/UI/执行循环（6.5）是接线前的下一步。

## 6. 模块审计发现（按模块分组，证据为 file:line）

> 分级标准：**P1** = 正常使用即触发的功能破坏或数据风险；**P2** = 安全深度防御缺口、
> 边缘条件正确性问题、或声明与实现偏差；**P3** = 整洁度与打磨。攻击前提为"主 WebView 已被攻破"
> 的深度防御类问题记 P2（理由：插件平台时代前端不可完全信任，但当前无直接利用面）。

### 6.1 核心引擎（10 crate，约 25,000 行 / 311 测试）

体检总表：除下述问题外，10 crate 生产代码零平台 `#[cfg]`、生产 unwrap/expect/panic 仅 3 处
（P3-23）、Cleanroom 之外无 stub。
