### 1.2 五条判断

1. **引擎层（安装 → 索引 → 启动）已经贯通并实机验证过**：Minecraft 能进渲染线程并创建窗口。
   这是整个项目最硬的一块，且已被 468 项测试 + 多次真实启动背书。
2. **产品层是"主线闭环 + 生态缺口"**：登录、建实例、装版本、装 loader、启停模组、改设置都能做；
   但 **Mod 浏览器（搜索/详情/安装）没有页面**，多账号管理、下载暂停/恢复、日志查看也没有入口。
3. **前后端接口面已收敛**（2026-10-21）：64 个命令、`api.ts` 全覆盖，
   `instance_*` 语义按 ADR-002 定稿；插件 15 条命令有 14 条接到 `/plugins` 页面。
4. **工程质量高于文档印象**：CI 三门门禁（fmt / clippy / 生产代码禁 `panic`+`unwrap`）本地全绿，
   300 项测试全绿，ts-rs 有新鲜度断言，capability 显式禁掉通用 `fs`/`shell`。
5. **结构性偿债已完成**（Phase 1）；剩下的主要是**发布工程 + 生态扩展**：体积审计/公证/updater、
   插件签名与目录（Phase 7）、Dashboard/隔离 UI/逻辑运行时（Phase 3–5）、Agent（Phase 6）。

## 2. 产品定位与硬约束

| 项 | 内容 |
|----|------|
| 名称 | RMCCC（Rust Minecraft Core Client），命名空间 `rmcl.snowebsite.top` |
| 形态 | 双入口：**桌面 GUI**（Tauri 2 + SolidJS）+ **CLI**（`rmcli`，同一套 core） |
| 目标平台 | macOS / Windows / Linux（CI 三平台矩阵） |
| 体积红线 | 最终二进制品 **< 10 MB**（AGENTS.md 硬约束；当前 GUI 未剥离 10.57 MB，仍待审计） |
| 对标 | HMCL（Java 版启动器）。大量结构直接对齐 HMCL 的类与方法命名（`GameRepository`、`DefaultLauncher`、`overrideProperties`、`IsolationType`） |
| 存储 | 全部 JSON 文件，可读可调试；无数据库依赖 |

**设计取舍（有意为之，不是欠账）**：

- **只有一套全局游戏默认值**，不做 HMCL 的"多套游戏设置预设"（`config/game-settings.json` 可多份）。
  实例通过 `parent` 引用预设的能力被简化为"全局默认值 + 实例覆盖"。
- **实例注册表就是 `ProfileStore`**（`profiles/{id}.json`），不扫描 `versions/` 反推实例。
  因此 HMCL 那套 `{instance_root}/.hmcl/config/` 的实例侧配置在 RMCCC 落在 profile JSON 里。
- **`isolation` 是三值枚举** `never | modded | always`，而 HMCL 是从 `overrideProperties`
  是否包含 `runningDirectory` 反推的布尔语义。

## 3. 技术栈与关键选型

| 层 | 选择 | 版本约束 | 理由 / 代价 |
|----|------|----------|-------------|
| 原生外壳 | Tauri 2.x | `tauri = 2` | 用系统 WebView，macOS 上免打包 Chromium |
| 前端框架 | SolidJS | `^1.9` | 无虚拟 DOM，产物 116 KB |
| 路由 | `@solidjs/router` | `^0.15` | 4 条路由，`Router root={App}` 承载常驻外壳 |
| 样式 | Tailwind CSS v4 + 手写设计系统 | `^4.3` | **实际样式以 `src/styles/app.css`（1,494 行）为主**，Tailwind 只提供 reset/工具类底座 |
| 类型桥 | ts-rs | 11.x | Rust struct → `src/ipc/types.ts`，CI 校验新鲜度 |
| 异步运行时 | tokio | `1`（multi-thread） | 下载并发、MS 轮询、进程监听 |
| HTTP | reqwest（rustls） | `0.12`，`default-features = false` | 不引 OpenSSL；连接池 32、connect 10s、总 120s |
| 加密 | AES-256-GCM + 本地 key file | `aes-gcm 0.10` | 无系统钥匙串依赖；key 文件 0600（Windows `icacls`） |
| 序列化 | serde / serde_json | `1` | 所有持久化格式 |
| 日志 | tracing + tracing-appender | — | 文件 + 控制台双输出，滚动 |
| 进程 | tokio::process | — | `ManagedProcess` 包装 + `ProcessListener` |
| 状态 | `dashmap` + `tokio::sync::RwLock` | — | 运行中进程表 / CoreContext 容器 |
| CLI | clap 4（derive） | — | 9 组子命令 + 统一输出信封 |

**体积相关**：`reqwest` 关掉默认特性、`zip` 只开 `deflate`；release profile 为
`opt-level = "s"`、`lto = true`、`codegen-units = 1`、`panic = "abort"`、`strip = true`
（根 `Cargo.toml`）。其中 `strip = true` 因缺 `libLLVM.dylib` 在本机 SIGABRT，属环境问题（§15.5）。

## 5. 分层架构

### 5.1 四层职责

| 层 | 位置 | 职责 | 不该出现的东西 |
|----|------|------|----------------|
| L1 基础 | `rmccc-error`、`rmccc-config` | 错误、路径、序列化、防抖写盘 | 业务规则 |
| L2 领域 | auth / download / version / launch / modloader / mods / profile | 各自领域的算法与 I/O，全部 async + trait 抽象 | 跨领域编排 |
| L3 编排 | `rmccc-core`（`CoreContext` + `pipeline`） | 持有全部 provider（DI）、编排安装/修复/启动、旧布局迁移 | UI 与参数解析 |
| L4 适配 | `src-tauri`（IPC）、`src-cli`（clap） | 参数适配、事件发射、输出渲染 | 业务规则 |

### 5.2 `CoreContext`（DI 容器）

`crates/rmccc-core/src/lib.rs:31` 起的字段，全部是 `dyn` 或具体类型，Tauri 与 CLI 共享同一套：

| 字段 | 类型 | 说明 |
|------|------|------|
| `config` | `AppConfig` | 全局设置（`config/launcher-settings.json`） |
| `launcher_state` | `LauncherState` | 可丢失的运行状态（`state/launcher-state.json`），与设置分离 |
| `user_settings` | `UserSettings` | 用户偏好（locale、检查更新） |
| `data_dir` | `PathBuf` | **实际**使用的数据目录（尊重 CLI `-d`，不是 `config.resolved_data_dir()`） |
| `http_client` | `reqwest::Client` | 共享连接池（32 idle/host、10s connect、120s total） |
| `download_manager` | `Arc<dyn DownloadManager>` | 并发下载 + 缓存 |
| `profile_store` | `ProfileStore` | 实例注册表 |
| `game_repository` | `Arc<RwLock<DefaultGameRepository>>` | 本地版本仓库（`versions/` 索引） |
| `version_provider` | `Box<dyn VersionProvider>` | Mojang 清单（仅安装时取元数据） |
| `download_provider` | `Box<dyn DownloadProvider>` | 镜像 URL 改写（official / BMCLAPI） |
| `auth_provider` | `Arc<dyn AuthProvider>` | 微软认证 |
| `account_repo` | `Arc<AccountRepository>` | 账户持久化（明文元数据 + 加密私密数据） |
| `file_saver` | `FileSaver` | 200ms 防抖写盘，进程退出前 flush |
| `modloader_providers` | `HashMap<ModLoaderType, Box<dyn ModLoaderProvider>>` | 旧 trait 体系，只注册了 Fabric/Forge/NeoForge；安装路径实际只用 Forge/NeoForge（Fabric 那条是死重） |
| `mod_sources` | `Vec<Box<dyn ModSource>>` | 当前只有 Modrinth |

**初始化副作用**（`CoreContext::new`）：读三份配置文件 → 强制 `config.data_dir = 传入目录` →
建 HTTP client → 建 SHA1 缓存仓库 → 建下载管理器 → **执行旧布局迁移**（`migrate_instance_layout`）
→ 构造 game repository 并 `refresh()`。

### 5.3 编排层 `pipeline`（唯一业务编排入口）✅ P1-3 已收口（2026-10-21）

| 函数 | 作用 | 调用方 |
|------|------|--------|
| `resolve_version` | 由版本 id 解析出可启动视图（本地 patched JSON 优先） | `install_game` |
| `install_game` | 安装版本（版本 JSON + client/libraries/assets 单批次 + natives） | Tauri `version_install`、CLI `version_install` / `resource_install` ✅ |
| `repair_instance` | 按完整性检查结果补下载（版本 id 入口） | Tauri `instance_repair` ✅ |
| `ensure_launch_ready` | 启动前置条件检查（profile 视图，委托 `repair_instance`） | Tauri `launch_start`、CLI `launch_start` / `resource_repair` ✅ |
| `launch_game` | 完整启动编排（解析 → Java → 鉴权 → 构造 → 监听 → spawn） | Tauri `launch_start`、CLI `launch_start` ✅ |
| `commit_install` | 安装提交（写 `game_version` + 刷新索引） | 两端共用 ✅ |
| `refresh_repository` | 重扫本地索引 | 两端共用 ✅ |

> **原问题**：安装、修复、启动三条主链路在 Tauri 各有一份复刻实现（`version.rs` 约 145 行、
> `instance_repair`、`launch_start`），修一处漏一处，且 GUI 那份没有单测。
> **现状**：Tauri 三个命令都退化为薄适配（事件/监听/并发护栏），编排只在 `rmccc-core::pipeline`
> 一处；`repair_resources`（第三份分叉实现、0 调用）已删除。
> 收益（顺带修掉的 bug）：GUI 安装现在会解压 natives；安装提交改用重读后的 profile，
> 不再用几秒前的快照覆盖用户设置；自定义 Java 路径不存在时立刻报 `JavaNotFound`（原先要到 spawn 才失败）。

### 5.4 错误模型

- `RmcccError`（`thiserror`）+ `ErrorCode`（20 个变体，`#[serde(rename_all = "snake_case")]`）。
- 错误码清单：`network_error`、`auth_failed`、`credential_expired`、`wrong_account`、
  `token_expired`、`download_failed`、`hash_mismatch`、`insufficient_disk_space`、
  `java_not_found`、`java_version_mismatch`、`game_crashed`、`profile_not_found`、
  `missing_dependency`、`mod_version_conflict`、`io_error`、`already_running`、
  `internal_error`、`validation_error`、`not_found`、`unknown`。
- IPC 边界用 `IpcError { code, message, retryable }`；`retryable` 供前端决定是否给"重试"按钮。
- CLI 侧再包一层输出信封 `{ ok, data | error: { code, exit_code, message } }`，`-o json|plain|auto`。

### 5.5 类型桥（ts-rs）

- `src-tauri/src/bindings.rs` 集中 `#[derive(TS)]` 导出，生成 `src/ipc/types.ts`（24 个导出）。

- 约定：`src/ipc/api.ts` 只写 wrapper，**不再手写与生成同名类型**（历史上手写的
  `SettingsUpdate` 曾遮蔽生成类型，导致字段变更后编译期才发现）。

## 6. 底层组件逐个说明

### 6.1 `rmccc-config` — 配置、路径与 `$schema` 协商

**职责**：数据目录推导、三份配置文件的读写、版本化 `$schema`、防抖写盘、locale/isolation 归一化。

**关键实现**：

- `paths.rs`：`default_data_dir()` = macOS `~/Library/Application Support/rmccc`；`config_dir` /
  `state_dir` / `log_dir` / `cache_dir`；`safe_join(root, sub)` 做路径穿越防护（有单测）。
- `schema.rs`：`SCHEMA_URL_PREFIX = https://rmcl.snowebsite.top/json/schema/`；
  `LEGACY_SCHEMA_URL_PREFIXES = [https://hmcl.huangyuhui.net/json/schema/]`；
  `check_schema()` 返回 `CompatibilityResult`，由 `SchemaStatus` 决定"可读 / 可保存 / 保留原 scheam"。
- `lib.rs`：`AppConfig`（全局设置，含本次新增的 8 个游戏默认值）、`LauncherState`（可丢失）、
  `UserSettings`（locale + check_updates）。`LoadResult.schema_upgraded` 触发**立即回写**，
  因此旧 HMCL 命名空间在加载时就变成新命名空间，不必等用户改设置。
- `file_saver.rs`：`DEBOUNCE_MS = 200`，后台线程窗口内合并同一路径的重复保存；
  `flush_and_shutdown()` 在 Tauri `RunEvent::Exit` 与 CLI 退出时调用。

**限制**：三个类型各自实现 `JsonSetting`（schema id/版本/默认值）与 `migrate_legacy`，
加载/备份/升级的通用逻辑虽由 `SettingFile<T>` 统一，但"旧路径迁移"仍是三份平行代码；
`AppConfig::load` 在 `$schema` 升级时**同步**回写，启动路径上多一次磁盘写。

### 6.2 `rmccc-auth` — 认证与凭据

**职责**：MS OAuth2 device flow、离线账号、token 加密存储、多账户仓库。

**关键实现**：

- `Account` trait + `AccountFactory`：`log_in()` / `play_offline()`；`CreateAccountContext` 注入
  共享 HTTP client。
- `microsoft.rs`：device code 授权 → 轮询 token → Xbox Live → XSTS → Minecraft services；
  进度经 `AuthProgress` 回调（Tauri 侧转成 `auth://device-code` 事件）。
- `offline.rs`：**UUID v3 = MD5("OfflinePlayer:" + name)**（官方算法，非 v5）。
- `vault.rs`：AES-256-GCM，12 字节随机 nonce + key 文件（32 字节，Unix 0600；
  Windows 用 `icacls` 收紧 ACL）。
- `repository.rs`：`accounts.json`（明文元数据）+ `private/account-private-data.json`（密文）分离；
  `load_active_account()` 是启动链路的唯一会话入口，内部做**提前刷新窗口**与 **profile UUID
  一致性校验**（不一致说明账号数据被替换，直接判 `WrongAccount`）。

**限制**：device flow 轮询逻辑与 UI 生命周期耦合在同一个命令里（长命令，无取消）。

### 6.3 `rmccc-download` — 下载引擎

**职责**：批量并发下载、SHA1 校验、重试、续传、去重缓存、镜像改写。

**关键实现**：

- `ConcurrentDownloadManager::download_batch(items, batch_id, on_progress)` → 并发度取自
  `config.download_concurrency`（1–64）。每个 item 可带 `sha1`、`size`、候选 URL 列表。
- `RetryConfig::delay_for_attempt`：指数退避。
- 续传：临时文件 + `Range` 请求（`resume`）。
- `CacheRepository`：`check_by_sha1()` 命中即硬链接/复制，避免同一 library 多实例重复下载。
- 批控制：`cancel_batch` / `pause` / `resume` 按 `batch_id`（**不是单文件**），
  对应 IPC `download_cancel/pause/resume`。
- `provider.rs`：`create_provider("mojang" | "bmclapi" | "bmclapi@<url>")` 做 URL 改写。

**限制**：Tauri 侧的进度经 `ThrottledEmitter` 按 `event_throttle_ms` 节流后发事件；
CLI 侧由 `Output::progress()` 直接打百分比行（`src-cli/src/output.rs:179`），无节流，
大量小文件时输出较密。

### 6.4 `rmccc-version` — 版本仓库与解析

**职责**：Mojang 清单、本地 `versions/` 索引、离线解析、资源布局、完整性检查。

**关键实现**：

- `DefaultGameRepository` 实现 `GameRepository` trait：`refresh()` 扫描 `versions/*/*.json` 建索引；
  `get_resolved(id)` 离线解析出 **双视图** `ResolvedVersion { launch, standalone }`：
  `launch` 展开 `inheritsFrom` 用于启动，`standalone` 保留完整库列表用于安装/分析。
- `manifest.rs`：`MojangVersionProvider` 拉 `version_manifest_v2.json`，`cache.rs` 带 TTL
  （`ttl_seconds`），断网时降级用旧缓存。
- `assets.rs` / `libraries.rs` / `arguments.rs`：资源索引、库规则（OS/arch）、参数模板替换。
- `file_layout.rs`：`versions/{id}/{id}.json|.jar`、`libraries/`、`assets/`、`natives-{platform}/`
  路径的唯一来源。
- `completion.rs`：`check_completion(game_dir, resolved) -> Vec<MissingItem>`。
- `isolation.rs`：`IsolationType::{Never, Modded, Always}`，`Modded` 为默认。
- `java_version_for_mc()`：无 `javaVersion` 字段时的兜底映射。

**限制**：索引是进程内内存结构 + `RwLock`，外部改动（用户手动删文件）需 `instance_refresh`
或重启才能反映。

### 6.5 `rmccc-launch` — 启动链路

**职责**：把 resolved 版本 + 认证 + `LaunchOptions` 变成一条命令行或一个启动脚本，并托管进程。

**关键实现**（`default_launcher.rs`，与 HMCL `DefaultLauncher` 同构）：

| 步骤 | 方法 | 说明 |
|------|------|------|
| 1 | `get_features()` | `has_custom_resolution` 等规则开关 |
| 2 | `get_configurations()` | 版本 JSON 的 `-D` 配置项 |
| 3 | `get_classpath()` | libraries + client jar 拼 classpath |
| 4 | `extract_log4j_configuration_file()` | 从版本 JSON 提取 log4j XML 到 `log4j-{ts}.xml` |
| 5 | `decompress_natives()` | 解压 natives 到 `natives-{platform}`，按 size 幂等跳过 |
| 6 | `generate_command_line()` | java → 内存/GC → 用户 JVM args → `-javaagent` → 主类 → 游戏参数 |
| 7 | 模板替换 | `${auth_player_name}`、`${version_name}`、`${game_directory}` 等 |
| 8 | `spawn_game()` | **response file**：把 token 等参数写入 `.launch-args-{uuid}`，命令行只留 `@file` |
| 9 | `schedule_response_file_cleanup()` | spawn 后延迟 5s 删除（JVM 解析命令行是异步的） |
| 10 | `mark_launched_abnormally()` | 写 `.abnormal` 标记；正常退出时清除 |

其余要点：

- **`run_dir` 与 `game_dir` 分离**：`game_dir` 是共享游戏根（versions/libraries/assets），
  `run_dir` 是 `--gameDir`、进程 cwd、`${game_directory}`、`INST_MC_DIR` 指向处，
  也是 `mods/`、`saves/` 所在。两者由 `options::instance_run_dir()` **唯一推导**，
  启动与模组命令共用，因此不可能再出现"安装目录 ≠ 启动目录"。
- **java 可执行文件不在 `jvm_args` 里**：`spawn_game()` 把它作为程序、`make_launch_script()`
  把它前置到脚本首行。历史上它曾被塞进 argfile 首行，导致 JVM 把它当主类
  （`could not find or load main class …/bin/java`）。
- `java.rs`：`detect_java_installations()` 扫标准路径；`find_java(required)` **优先精确匹配，
  其次取"≥ required 里最小的"**（避免 Java 25 的模块路径限制问题）。
- `managed.rs` / `process.rs` / `process_listener.rs`：进程包装、退出类型判定（`ExitType`）、
  `ProcessListener` 回调（`on_log` / `on_exit`）。
- `wrapper`、`pre_launch_command` / `post_exit_command`、`env_vars`、进程优先级
  （`nice` / Windows priority class）。

**限制**：`natives` 解压未做 zip-slip 归一化（§15.4）；启动脚本的分支（sh/bat/ps1）无单测。

### 6.6 `rmccc-profile` — 实例注册表与继承模型

**职责**：实例 JSON 存储、字段级"继承 vs 覆盖"、生效值合并。

**关键实现**：

- `ProfileStore`：`profiles/{id}.json`，**原子写**（`{id}.json.tmp` → rename，有单测断言不残留 tmp）。
- `Profile` 字段分三层：
  1. 身份：`id`、`name`、`game_version`、`icon`、`created_at`、`last_played`；
  2. 加载器与目录：`mod_loader`、`isolation`、`game_dir`；
  3. 22 个可继承字段（`java_path`、`jvm_args`、`memory_mb`、`width`、`wrapper`、`env_vars` …）
     + `override_properties: BTreeSet<String>` 覆盖名单。
- `fields::{JAVA_PATH, …, ALL}`：字段名常量与白名单。`set_overridden` 只收白名单内的名字，
  拼错的名字不会让字段"悄悄变成不可继承"。
- `Profile::resolve(&AppConfig) -> ResolvedInstanceSettings`：逐字段 `is_overridden()` 决定取实例值
  还是全局默认值。**值与会话标志分开存**：取消覆盖不丢用户填过的值。
- `effective_isolation()`：`None` → 全局 `default_isolation`（默认 `modded`）。

**限制**：`ResolvedInstanceSettings` 不落盘、不进 IPC（只用于启动与模组路径推导），
前端展示的"生效值"是本地按同样规则算的（存在两处规则实现，见 §15.2 P2-8）。

### 6.7 `rmccc-modloader` — 8 种加载器

**职责**：加载器版本列表、安装（生成 patch JSON、下载库、跑 installer）、依赖注入、库分析。

**关键实现**：

- `ModLoaderType::{Fabric, Forge, NeoForge, Quilt, LiteLoader, OptiFine, Cleanroom, LegacyFabric}`
  + `all()` / `display_name()` / `library_id()`。
- **两套体系并存**（真实存在的结构债）：
  - 旧：`ModLoaderProvider` trait + `create_provider()`（`lib.rs:150`），由 `CoreContext` 持有，
    **只有 Forge / NeoForge 走这条**（要下载 installer JAR 并执行）。`CoreContext` 还为 Fabric
    注册了一个 provider，但安装路径并不用它（死重）。
  - 新：`DependencyManager`（`lib.rs:177`），**其余 6 种走这条**（纯 HTTP + JSON patch，
    把 patch 后的 `GameVersion` 落盘到 `versions/{id}/{id}.json`）。
  - 分流逻辑在 `src-tauri/commands/modloader.rs:105` 与 `src-cli/context.rs:668` **各写了一遍**
    （注释里自称"与 CLI 一致的分流"，实际是复制粘贴）。
- `patch.rs`：把 loader 的 libraries 合并进原版 version JSON，生成 `{version}-{loader}` 实例 id。
- `analyzer.rs`：从 libraries 反查 loader 类型与版本（`LibraryAnalyzer::analyze`）。
- `cleanroom/*`：**stub**，`install_task.rs:13` 直接返回 `"Cleanroom install not yet implemented"`。

**限制**：Cleanroom 不可用；CurseForge 加载器生态未接；`DependencyManager` 只做"列 + 装"，
没有依赖冲突解析（`ModDependency` 类型在 `rmccc-mods` 中定义但无使用方）。

### 6.8 `rmccc-mods` — 模组源与本地管理

**职责**：`ModSource` trait（搜索/版本/下载链接/安装）、Modrinth 实现。

**关键实现**：

- `ModSearchQuery`（query/game_version/loader/page/limit）→ `ModSearchResult`。
- `ModrinthSource`：`search`、`list_versions`、`get_download_url`、`download_bytes`，
  4 个 async 测试用 wiremock 风格假响应验证解析。
- 本地管理不在这个 crate：安装/启停/删除由 Tauri `mods.rs` 直接做文件操作——
  `mods/` 与 `mods/disabled/` 之间移动文件实现启停；`sanitize_filename` + `validate_mod_filename`
  防路径穿越。

**限制**：只有 Modrinth；无依赖解析；**本地文件安装未实现**（缺 `tauri-plugin-dialog`）。

### 6.9 `rmccc-core` — 编排、迁移与会话

**职责**：DI 容器、pipeline 编排、旧布局迁移、会话刷新。

**关键实现**：

- `migrate_instance_layout()`（`lib.rs:329`）：把旧的 `instances/{id}/versions|libraries|assets`
  并入共享游戏根；`adopt_instance_tree()` / `merge_tree()` 做递归移动。
- **刻意不自动收养**：孤儿目录只在日志里 `WARN Orphaned pre-migration instance directory`，
  避免用户删掉实例后空间又被悄悄占回来。
- `refresh_session_if_needed()` / `log_in_active_account()`：启动与游戏启动前统一走这里，
  保证"提前刷新窗口 + UUID 一致性"只有一份实现。
- `flush_pending_writes()`：退出前清空防抖队列。

## 7. 数据与存储布局

### 7.1 磁盘树（本机实测）

```
~/Library/Application Support/rmccc/          # data_dir
├── accounts.json                 # 账户公开元数据（uuid / username / provider / 选中项）
├── user-settings.json            # UserSettings（$schema + locale + check_updates）
├── config/
│   └── launcher-settings.json    # AppConfig（全局默认值、目录、并发、镜像）
├── state/                        # 首次写状态时创建（本机当前尚未生成）
│   └── launcher-state.json       # LauncherState（可丢失：上次选中、窗口等）
├── private/
│   └── account-private-data.json # AES-256-GCM 密文（token）
├── profiles/
│   └── {uuid}.json               # 实例注册表（22 可继承字段 + override_properties）
├── logs/                         # tracing 滚动日志（log_get 读最新一个）
└── instances/                    # 共享游戏根（= game_root_dir 默认值）
    ├── versions/{id}/{id}.json|.jar
    ├── libraries/                # Maven 布局
    ├── assets/{indexes,objects}
    ├── downloads/  launcher_profiles.json
    ├── mods/  mods/disabled/     # 非隔离实例共享；隔离实例在自己的 run_dir 下
    └── {instance_id}/            # 隔离实例的运行目录（saves/options.txt/mods）
```

> `game_root_dir` 可由用户在设置页改到任意绝对路径；改完后 `instances/` 不再使用。
> `cache/`（SHA1 去重缓存）与 `state/` 都是**按需创建**：本机实测这两者尚未生成，
> 说明当前还没有走过一次带缓存的完整下载。

### 7.2 文件职责与写入路径

| 文件 | 写入者 | 时机 | 写策略 |
|------|--------|------|--------|
| `config/launcher-settings.json` | `settings_set` / CLI `config set` | 用户改设置 | `FileSaver` 200ms 防抖 |
| `state/launcher-state.json` | core / 命令层 | 状态变化 | 防抖；读失败容忍（坏文件自动备份重建） |
| `user-settings.json` | `settings_set_user` / `setLocale()` | 改语言 | 防抖 |
| `accounts.json` + `private/…json` | `AccountRepository::save()` | 登录/刷新/切换 | 元数据与密文分文件；密文整体重写 |
| `profiles/{id}.json` | `ProfileStore::save()` | 实例 CRUD/设置保存 | **原子写**（tmp → rename） |
| `.launch-args-{uuid}` | `DefaultLauncher::spawn_game()` | 每次启动 | 临时文件，spawn 后延迟 5s 删除；下次启动清扫残留 |

### 7.3 版本化与兼容

- 三份配置各有独立 schema id 与版本号（`launcher-settings` / `launcher-state` / `user-settings`，
  均 `1.0.0`）。
- 读到**旧命名空间**（HMCL）→ 立即以新命名空间回写（`schema_upgraded`）。
- 读到**未来版本** → `SchemaStatus` 判为只读，不覆盖用户文件。
- 坏 JSON → `backup_invalid_config` 改名保留，随后用默认值重建。

### 7.4 两套"实例"概念（读代码时最容易踩的坑）

RMCCC 里 **profile** 与 **instance** 不是同一个东西，这是 HMCL 移植留下的双概念：

| | `profile`（实例卡片） | `instance`（仓库实例） |
|---|---|---|
| 位置 | `profiles/{uuid}.json` | `versions/{id}/{id}.json` |
| 主键 | **UUID** | **版本 id**（如 `26.3`、`26.3-fabric`） |
| 谁在用 | 前端 Dashboard / 实例设置页 / 启动 / 模组 | `GameRepository` 索引、`instance_*` 7 个命令 |
| 关系 | 一个 profile 通过 `game_version` 指向某个 instance | 一个 instance 可被多个 profile 引用 |

后果：

1. `instance_rename` / `instance_duplicate` / `instance_remove` 改的是**版本 id 与 `versions/` 下的目录**，
   不是用户看到的实例名（`profile.name`）；`instance_remove` 会 `remove_dir_all(versions/{id})`。
2. 因此这 4 个命令在前端"没有对应入口"并不是漏做，而是**概念不对齐**：正确做法是给 profile 增加
   "重命名 / 复制 / 删除游戏文件"语义，或者让 HMCL 式的"实例 = 版本目录"成为唯一模型。
3. 当前 `profile_delete` 只删 JSON（`cleanup = false`），所以删卡片不会删游戏文件——
   这是安全的默认，但用户会看到"删了实例，磁盘空间没变"。

> 建议：在 `ARCHITECTURE.md` §3.3 明确这两个概念，并决定长期收敛方向（推荐保留 profile 作为唯一
> 用户可见实体，`instance_*` 降级为内部维护命令或直接删除）。

## 8. 设置模型（全局 / 实例 / 生效值）

### 8.1 三层结构

```
AppConfig（全局默认值）          profile.override_properties（字段名集合）
        │                                   │
        └──────────► Profile::resolve() ◄───┘
                          │
                          ▼
             ResolvedInstanceSettings（生效值，不落盘）
                          │
                          ▼
        LaunchOptions::from_profile()  →  DefaultLauncher
```

- **继承是默认**：字段不在 `override_properties` 中 → 用全局值，实例值被忽略但**保留在磁盘**。
- **覆盖是显式**：UI 上每个字段一个 🔓/🎚 开关，切换只改集合，不改值。
- **白名单校验**：后端只接受 `fields::ALL` 中的名字。

### 8.3 隔离（两套概念，别混淆）

| 概念 | 取值 | 影响 |
|------|------|------|
| `isolation` | `never` / `modded`(默认) / `always` | **只影响运行目录**（`run_dir`） |
| `game_dir` | 共享游戏根 | 版本、libraries、assets 永远共享，只有一份 |

- `never`：所有实例共用根目录运行（存档/mods 混在一起）。
- `modded`：只有装了 loader（有 patch）的实例用自己的 `run_dir`。
- `always`：每个实例都用 `instances/{id}/` 作为 `run_dir`。
- 模组目录**跟随 `run_dir`**，因此隔离实例天然拥有独立 mods。

### 8.4 与 HMCL 的对照

| HMCL | RMCCC | 差异 |
|------|-------|------|
| `config/game-settings.json` 可多套预设 | `config/launcher-settings.json` 单一全局 | 有意简化 |
| `Instance.overrideProperties` 字段名集合 | `Profile.override_properties` | 一致 |
| `IsolationType` 由 `runningDirectory` 推导 | 显式三值 `isolation` | 更直观，但语义不完全等价 |
| 实例配置在 `{instance}/.hmcl/config/` | 在 `profiles/{id}.json` | 因注册表不同 |

## 9. 安全设计

| 面 | 措施 | 位置 |
|----|------|------|
| Token 静态存储 | AES-256-GCM；12B nonce；key 文件 0600（Win `icacls`） | `rmccc-auth/src/vault.rs` |
| Token 传输 | **response file**（`@argfile`），启动后延迟删除 + 下次启动清扫 | `rmccc-launch/src/default_launcher.rs:715+` |
| Token 泄露面 | `ps aux` 看不到 `--accessToken`（在文件里，文件本身在短暂窗口内可读） | 同上 |
| 前端权限 | capability **不含** `fs:*` / `shell:*`；只开 window/event/process/window-state/opener/updater | `src-tauri/capabilities/default.json` |
| 外部链接 | 单一 `open_external_url` 命令，只开 http(s) | `commands/external.rs` |
| 路径穿越 | `safe_join()`；mod 文件名 `sanitize_filename` + `validate_mod_filename` | `rmccc-config/src/paths.rs`、`commands/mods.rs` |
| 配置损坏 | 坏文件备份后重建，不静默覆盖 | `rmccc-config/src/file_utils.rs` |
| 依赖漏洞 | CI `cargo audit` | `.github/workflows/ci.yml` |

**已知缺口**：natives 解压用 `natives_dir.join(entry_name)` 直接写入，**未做 zip-slip 归一化**
（仅按扩展名 `dll|so|dylib|jnilib` 过滤）。实际风险被"库文件的 SHA1 校验 + 官方源"前置削弱，
但不满足纵深防御（§15.4, P2）。

### 10.1 路由与外壳

| 路由 | 页面 | 行数 | 职责 |
|------|------|-----:|------|
| `/` | `Dashboard` | 1,128 | 注册表驱动的 CSS Grid：账户/实例/版本三个内置 Widget + 插件卡片；拖放/宽度循环/隐藏/恢复/重置；创建实例弹窗、启动面板、日志面板 |

| `/settings` | `Settings` | 455 | 游戏目录、内存、Java 检测、语言、**全局游戏默认值** |
| `/instances/:id` | `InstanceSettings` | 1,197 | 8 分区 / 22 字段继承开关 / 隔离 / Java / 内存参数 / 窗口进程 / 加载器安装 / 模组管理 / 高级 |

`main.tsx` 用 `<Router root={App}>`，`App.tsx` 常驻：`TitleBar`（自绘标题栏，可拖动）+
`.app-root` 容器 + `{children}` + `ToastContainer`，`onMount` 里 `initI18n()` → `win.show()`
→ `setFocus()` → 显示器可达性校验（`ensureReachable()`）。

### 10.2 状态与数据流

- **无全局 store**：每页用 `createSignal` / `createMemo`，数据在 `onMount` 里拉取。
- **调用方式（2026-10-20 已修，P2-11）**：路由页现在**调用 `api.ts` 分域 wrapper**
  （`auth.getSession()` / `profiles.list()` / `mods.toggle(...)` 等），不再裸写
  `safeInvoke<T>("命令名", { 参数 })`。`api.ts` 的 wrapper 已全部改为
  `safeInvoke`，统一返回 `{ ok, data } | { ok, error }`，命令名与参数名封装在 `api.ts` 内，
  路由层不再有裸字符串命令名。Dashboard 的 `auth, profiles, versions, launch` 四个 import
  从"未使用"变为真正使用（并新增 `downloads`）。
  另有 3 个命令经 `src/i18n/index.ts` 的 `userSettings` wrapper 间接调用，
  合计 UI 可直达 38 个（新增 `/mods`、账户管理、日志、完整性入口）。
- `api.ts`（192 行）的分域 wrapper **不再是死代码**：`auth` / `profiles` / `versions` / `launch` /
  `mods` / `modLoader` / `downloads` / `instances` / `settings` / `logs` / `external` 均由路由或
  i18n 调用。`mods` 在 `InstanceSettings` 内以 `mods as modsApi` 别名导入，避免与局部
  `createSignal` 的 `mods` 遮蔽。
- **事件**：Dashboard 订阅 `launch://started|output|exited`、`download://progress|complete|error`；
  Login 订阅 `auth://device-code`；`onCleanup` 统一 `unlisten`。`events.ts` 已补
  `INSTANCES_REFRESHED = "instances://refreshed"`，与后端 12 个常量对齐。

### 10.3 i18n

- `locales/en.ts` 是参考包（`as const` 推导 `TranslationKey`），`zh-CN.ts` 声明为
  `Record<TranslationKey, string>` → 缺键/多键在 `pnpm typecheck` 阶段就红。
- 解析顺序：`UserSettings.locale` → WebView 系统语言（`navigator.languages`）→ 回退 `DEFAULT_LOCALE = en`。
- 归一化：`en-US → en`；`zh` / `zh-TW` / `zh-Hans-CN → zh-CN`（与 Rust `resolve_locale` 一致）。
- 运行时切换 `setLocale(null | "en" | "zh-CN")` 落库并即时重渲染。

### 10.4 样式

- `src/styles/app.css` 1,494 行：CSS 变量色板 + 组件类（`.app-root`、`.titlebar`、
  `.profile-card`、`.settings-section`、`.modal-*`、`.toast-*`）。
- Tailwind v4 已接入（`@import "tailwindcss"`），实际大量组件用自定义类，Tailwind 主要提供
  reset 与少量工具类。
- 2026-10-21（Phase 3）：新增 `--rmccc-*` 主题令牌层 + 浅/深/跟随系统；插件主题只读 JSON。暗色不再是唯一主题。

### 10.5 IPC 可达性（审计重点）

| 分类 | 数量 | 说明 |
|------|-----:|------|
| UI 可直达 | **38** | 6 个页面/分区实际调用 |

## 附录 C：术语表

| 术语 | 含义 |
|------|------|
| **instance / profile** | 一个游戏实例。RMCCC 里两者同义：`profiles/{id}.json` 是注册表，`instances/{id}/` 是隔离时的运行目录 |
| **game root / game_dir** | 共享游戏根（≈ `.minecraft`），版本/库/资源只存一份 |
| **run_dir** | 实例的运行目录：`--gameDir`、cwd、`${game_directory}`、mods/saves 所在 |
| **isolation** | 决定 `run_dir` 是否等于实例目录。`never` / `modded` / `always` |
| **override_properties** | 实例覆盖名单（HMCL 同名概念），只存字段名，不存值 |
| **resolved version** | 把 `inheritsFrom` 展开后的版本视图，分 `launch` / `standalone` 两份 |
| **patch** | 加载器安装后生成的 `{version}-{loader}` 版本，`inheritsFrom` 指向原版 |
| **argfile / response file** | JVM `@file` 参数，用来把 token 从命令行挪进临时文件 |
| **batch_id** | 一次批量下载的标识，用于取消/暂停/恢复 |
